# External Integrations

**Analysis Date:** 2026-07-11

## APIs & External Services

**LLM Inference:**
- OpenAI-compatible chat-completions endpoint - plans and runs agent loops against local or cloud-compatible model servers
  - SDK/Client: `httpx` through `OpenAICompatibleLLMProvider` in `api/loopforge/providers.py`
  - Endpoint: `{LOOPFORGE_OPENAI_COMPATIBLE_BASE_URL}/chat/completions`
  - Auth: `LOOPFORGE_OPENAI_COMPATIBLE_API_KEY` as a Bearer token
  - Model: `LOOPFORGE_OPENAI_COMPATIBLE_MODEL`
  - Compatibility targets documented in `README.md`: cloud providers, vLLM, LM Studio, Ollama-compatible gateways, and internal inference servers

**Agent Runtime:**
- opencode server - optional in-sandbox alternative to the native ReAct engine
  - SDK/Client: optional `opencode-ai` package, lazily loaded in `api/loopforge/runtime.py`
  - Server: per-run `opencode serve` container launched by `DockerGvisorSandboxProvider.serve_opencode()` in `api/loopforge/providers.py`, or an externally supplied server at `LOOPFORGE_OPENCODE_HOST`/`LOOPFORGE_OPENCODE_PORT`
  - Auth: resolved model credentials are injected into the isolated container as `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` by `api/loopforge/runtime.py`
  - Configuration: locked-down `opencode.json` generated by `api/loopforge/opencode_config.py`

**Container Runtime:**
- Docker Engine with gVisor - executes generated Python and hosts the optional opencode server
  - SDK/Client: Docker CLI invoked with Python `subprocess` from `api/loopforge/providers.py`
  - Auth: local Docker daemon access; no application credential
  - Runtime: `LOOPFORGE_DOCKER_GVISOR_RUNTIME`, default `runsc`

**Browser-to-Backend API:**
- LoopForge FastAPI REST API - frontend operations use relative `/api/*` routes through `web/src/lib/api/client.ts` and feature-specific modules under `web/src/lib/api/`
  - SDK/Client: browser `fetch`, coordinated through TanStack React Query
  - Base URL: `VITE_API_BASE`, or same-origin with the Vite `/api` proxy in `web/vite.config.ts`
  - Auth: none

## Data Storage

**Databases:**
- SQLite local database
  - Connection: filesystem path from `LOOPFORGE_STORAGE_PATH`, default `.loopforge/loopforge.db`
  - Client: Python `sqlite3` standard library in `api/loopforge/sqlite_store.py`
  - Mode: WAL with a single JSON-payload `records` table and indexes by goal and run

**File Storage:**
- Local filesystem only
  - Uploaded datasets: `LOOPFORGE_DATASET_STORAGE_PATH`, default `.loopforge/datasets`, written by `api/loopforge/app.py`
  - Ephemeral agent workspaces: `LOOPFORGE_DOCKER_WORKSPACE_ROOT`, default `/tmp/loopforge-workspaces`, managed by `api/loopforge/providers.py`
  - Dataset files are mounted read-only into execution containers at `/workspace/data/`

**Caching:**
- No external cache is integrated
- TanStack React Query keeps browser-side request state in memory through `web/src/app/Providers.tsx`

## Authentication & Identity

**Auth Provider:**
- None detected
  - Implementation: `api/loopforge/app.py` exposes the API without authentication middleware; CORS permits `http://localhost:5173`
  - LLM provider credentials are service secrets, not user identity; persisted provider keys are encrypted by `SecretCipher` in `api/loopforge/secrets.py`

## Monitoring & Observability

## Environment Configuration

**Required env vars:**
- Model use requires `LOOPFORGE_OPENAI_COMPATIBLE_BASE_URL`, `LOOPFORGE_OPENAI_COMPATIBLE_API_KEY`, and `LOOPFORGE_OPENAI_COMPATIBLE_MODEL`; defaults in `api/loopforge/settings.py` are local-development placeholders
- Persistent secret encryption requires a deployment-specific `LOOPFORGE_SECRET_KEY`
- Real sandbox execution requires `LOOPFORGE_SANDBOX_PROVIDER=docker_gvisor` plus suitable `LOOPFORGE_DOCKER_GVISOR_RUNTIME`, `LOOPFORGE_DOCKER_SANDBOX_IMAGE`, workspace, network, memory, and CPU settings
- Optional opencode execution requires `LOOPFORGE_AGENT_ENGINE=opencode`, an opencode image/network, and the `LOOPFORGE_OPENCODE_*` settings in `api/loopforge/settings.py`
- Frontend cross-origin deployments use `VITE_API_BASE`; same-origin builds and local Vite proxying can omit it

**Secrets location:**
- Process environment or the root `.env` file loaded by `api/loopforge/settings.py`; `.env` exists and was not read for this analysis
- Stored LLM-provider API keys live as authenticated encrypted values in SQLite, produced by `api/loopforge/secrets.py`; `LOOPFORGE_SECRET_KEY` protects them
- opencode receives resolved credentials only as per-container environment variables assembled in `api/loopforge/runtime.py`; keys are not written into `opencode.json`

## Webhooks & Callbacks
